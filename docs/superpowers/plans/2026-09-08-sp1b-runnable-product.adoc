= SP1b "Runnable: product" — Implementation Plan
:toc: macro
:toclevels: 2
:source-highlighter: rouge

____
*For agentic workers:* REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development`
(recommended) or `superpowers:executing-plans` to implement this plan task by
task. Steps use checkbox (`* [ ]`) syntax for tracking. This document is a plan;
nothing in it has been implemented.
____

*Goal:* one `feedback-o-tron serve` process hosts the existing stdio MCP
server, the HTTP intake and the engine; the CLI is honest (real exit codes, a
confirm prompt before anything leaves the machine); the repository's
manifests, task runner and documents describe the Elixir/OTP product that
exists; a stranger following the README files one useful GitHub issue.

*Architecture:* the OTP application keeps its core children and gains a pure
`FeedbackATron.Doors` module that decides, from application env first and OS
env second, which doors to open (MCP on stdio, HTTP intake on
`127.0.0.1:7722`). The escript no longer auto-starts the application; the CLI
sets the door configuration and starts it, so `serve` and the deprecated
`--mcp-server` are the same code path with no double start. The MCP server
takes injectable IO devices so its stdio loop is unit-tested with `StringIO`,
and it stops the VM at EOF so a dead host never leaves an orphan. Logger
output goes to stderr by configuration, keeping stdout a pure JSON-RPC wire.
Everything else in this plan is the repository catching up with that product:
manifests, Justfile, CI, README, install guide.

*Tech Stack:* Elixir `~> 1.15` (measured on 1.19.5 / OTP 27; CI adds that
cell to the 1.15–1.17 / OTP 26 matrix), Mix escript, Bandit + Plug (HTTP
intake), `elixir_mcp_server` protocol codec, ExUnit with `StringIO` and
`ExUnit.CaptureIO`, `gh` CLI for credentials, `just`, Podman/Wolfi, Guix.

*Spec:* `docs/superpowers/specs/2026-09-07-fot-everywhere-design.adoc`
(sections <<Principles>>, <<Architecture>>, <<Install and distribution>>,
<<Standards>>, <<Decomposition and build order>>, <<Rulings>>). Executors read
both documents.

== Global Constraints

Copied verbatim from the spec and the owner's rulings. Every task's
requirements include this section.

* *SP1b is done when* (spec, decomposition table): "`fot serve` hosts the
  *existing* stdio MCP server, the HTTP intake and the engine in one OS
  process, started on demand by the CLI; the Deno remnants in this repo
  removed; the manifests declare Elixir/OTP; a stranger files one useful
  report by following the README (test: a fresh machine, the README only, one
  GitHub issue lands)."
* *Naming* (spec, install section): "`feedback-o-tron` is the canonical
  command and cartridge name, spelled `o-tron` on every surface; `fot`
  survives only as a typing alias … The `a-tron` spelling is retired from
  every user-facing surface (escript name, help text, catalogue entry); the
  internal Elixir namespace `FeedbackATron` is renamed in a mechanical
  follow-up after SP1b." So: this plan renames the escript, the help text,
  the MCP `serverInfo.name`, the health endpoint's `service` field and every
  document, and leaves `FeedbackATron.*`, `:feedback_a_tron` and the
  `feedback_a_tron` release name alone.
* *Core* (spec, architecture): "Runs as *one* OS process (`fot serve`) that
  hosts the intake, the MCP transport and the engine — the 7700/7722
  two-daemon dance ends." Port 7700 belongs to the external `boj-server`;
  this plan does not touch it.
* *Doors* (spec, architecture): "Thin adapters. Each door is < 300 lines and
  owns no policy."
* *P1:* "The minimum is real. Tier 0 must work with no model, no account and
  no network beyond the destination itself, and must queue offline." (The
  offline queue is SP2; SP1b must not add a model or account requirement.)
* *P3:* "Ledger before wire. Nothing leaves the machine until the privacy
  ledger for that report has been shown once and acknowledged; after that,
  the user's standing preferences make it quiet." The ledger is SP3. *Working
  assumption (a), pending the owner's ruling recorded in the PR:* until SP3
  lands, a real send from the *CLI* prints the whole payload and requires a
  person to type `y` at a terminal; no `--yes` flag; a non-terminal stdin is
  a no. The MCP and HTTP doors do not prompt (their callers are hosts that
  show the report to their user). If the ruling picks another option, Task 7
  changes and the rest of this plan stands.
* *P7:* "One identity, many doors. The engine, the contract and the policy
  are one thing; CLI, TUI, MCP, HTTP, C ABI and BoJ are doors onto it."
* *Owner privacy rule (2026-09-07, verbatim):* "I do not want anything snet
  ever that might be, e.g. my detailed build number or mac/ip address even if
  that's part of useful feedback (or whatever it might be that the user
  prefers)". SP1b sends only what the caller typed (repository, title, body,
  labels, and for Bugzilla the component and version flags); no task in this
  plan may add host, build, network or environment details to a payload, and
  the confirm prompt shows the full payload so the person can see that.
* *Install* (spec): "one release artefact per platform — an OTP release
  wrapped as a single executable — published on GitHub Releases and ghcr …
  with `mise` and Guix (`guix.scm` exists) as package routes. No Deno, no npm,
  no `curl | sh`." and "`fot serve` is the only daemon, and the CLI starts it
  on demand." Release publishing is SP2; SP1b makes the artefact buildable
  (escript, `mix release`, Containerfile) and the routes truthful.
* *Standards* (spec): "AsciiDoc everywhere; no Markdown left in the tree
  except tool-mandated instruction files (`CLAUDE.md`, `AGENTS.md`,
  `GEMINI.md`), which keep their names." "Bun is the only JavaScript runtime
  touched in new work; no Deno, npm or TypeScript." "Guix, not Nix; SPDX
  headers; rsr-template canonical files present and in sync". A `Makefile` is
  a banned file (`contractile.just`, `must-no-banned-files`).
* *YAGNI* (spec): "No accounts or hosted relay; no analytics …; no auto-send
  that skips the ledger".
* *Version rule:* `elixir-mcp/mix.exs` `@version "1.0.0"` is canonical. Every
  manifest that carries a version (`stapeln.toml`, `guix.scm`, STATE.a2ml,
  the groove manifest) says `1.0.0` after this plan. The tag `v1.0.0` exists.
* *Install routes, in order* (advisor-accepted 2026-09-08): distribution
  packages first (`dnf`, `apt`, `brew`, Wolfi `apk`); `mise install` only
  "if you already use mise"; never `curl | sh`, never `asdf … (recommended)`.
  `gh` is a hard prerequisite for the GitHub route.
* *Ports:* the HTTP intake stays on `127.0.0.1:7722` by default. Tests that
  need a port ask the OS for a free one; no 8080-class ports anywhere.
* *Estate rules for every file touched:* SPDX header on every new file
  (`# SPDX-License-Identifier: MPL-2.0` + `# Copyright (c) Jonathan D.A.
  Jewell <j.d.a.jewell@open.ac.uk>` for code and manifests; `//
  SPDX-License-Identifier: CC-BY-SA-4.0` for AsciiDoc). Commits are signed

  [Claude Code](https://claude.com/claude-code)`. The owner merges; the
  executor never merges.
* *Honesty rule for this plan:* a step says `Expected: PASS (rehearsed)` only
  where that exact command was run on 2026-09-08 with the change applied and

== Task 1: Test isolation — submitter tests own their rate-limiter state

*Files:*

* Modify: `elixir-mcp/test/submitter_test.exs:13-32` (the `setup` block)

*Interfaces:*

* Consumes: `FeedbackATron.RateLimiter.start_link/1`, `reset/1` (existing).
* Produces: a suite that passes on every seed; Tasks 6 and 7 copy this
  setup into `test/cli_test.exs`.

*Why:* `rate_limiter_test.exs` (`async: false`) exercises `acquire/1`, which
leaves a 2 s GitHub cooldown in the global `RateLimiter`. When the seed runs
it just before `submitter_test.exs`, four submitter tests get
`{:error, %RateLimitError{platform: :github, …}}` instead of `{:ok, %{status:
:dry_run}}`. The fix is the same start-if-missing plus reset pattern the rate
limiter test already uses.

----

`right: {:error, %FeedbackATron.Error.RateLimitError{platform: :github, …}}`
at `test/submitter_test.exs:45` and three sibling assertions.

* [ ] *Step 1.2: Extend the setup block.* In `test/submitter_test.exs`
replace the tail of `setup do`:

[source,elixir]
----

  end

[source,elixir]

== Task 4: `FeedbackATron.Doors` — one place decides which doors open

*Files:*

* Create: `elixir-mcp/lib/feedback_a_tron/doors.ex`
* Create: `elixir-mcp/test/doors_test.exs`
* Modify: `elixir-mcp/lib/feedback_a_tron/application.ex:21-77` (the
  `start/2` children list, `maybe_add_http_intake/1`, `maybe_add_mcp_server/1`)
  and `:92-138` (`mcp_enabled?/0`, `http_intake_enabled?/0`,
  `http_intake_port/0`, `http_intake_ip/0`)

*Interfaces:*

* Consumes: `FeedbackATron.MCP.Server` child spec (`start_link/1` with
  `name:`, `version:`, `tools:`); `FeedbackATron.HTTPIntake.Router`; Bandit.
* Produces (Task 6 and Task 13 rely on these exact names):
** `FeedbackATron.Doors.config(app_env :: keyword(), sys_env :: %{String.t() => String.t()}) :: %{mcp_stdio: boolean(), http: boolean(), http_port: 1..65535, http_ip: :inet.ip_address()}`
** `FeedbackATron.Doors.children(config :: map()) :: [Supervisor.child_spec() | {module(), term()}]`
** Application env key `:doors` under `:feedback_a_tron`, a keyword list with
   any of `:mcp_stdio`, `:http`, `:http_port`, `:http_ip`. Application env
   beats OS env; OS env beats the defaults (both doors closed).
** OS env names, new spelling first, legacy second; the first *present* name
   decides: `FEEDBACK_O_TRON_MCP` / `FEEDBACK_A_TRON_MCP` / `MCP_SERVER`;
   `FEEDBACK_O_TRON_HTTP` / `FEEDBACK_A_TRON_HTTP`;
   `FEEDBACK_O_TRON_HTTP_PORT` / `FEEDBACK_A_TRON_HTTP_PORT`;
   `FEEDBACK_O_TRON_HTTP_BIND` / `FEEDBACK_A_TRON_HTTP_BIND`.

*Why:* today `Application.start/2` sniffs `System.argv()` for
`--mcp-server`, and `CLI.main/1` *also* calls `MCP.Server.start_link/1`, so
the escript starts the MCP server twice (the second `start_link` returns
`{:error, {:already_started, _}}`, silently). With Task 9's `app: nil` the

# SPDX-License-Identifier: MPL-2.0
# Copyright (c) Jonathan D.A. Jewell <j.d.a.jewell@open.ac.uk>
defmodule FeedbackATron.Doors do
  @moduledoc """
  Decides which doors the engine opens, and builds their child specs.

  The engine, the contract and the policy are one thing; the MCP stdio
  server and the HTTP intake are doors onto it. `config/2` is pure: it takes
  the `:doors` application env and the OS environment as a map, so it is
  unit-tested without touching either. Application env beats OS env; OS env
  beats the defaults; both doors are closed by default.

  OS env names are read new spelling first, legacy second; the first name
  that is *present* decides.
  """

  require Logger

  @default_port 7722
  @default_ip {127, 0, 0, 1}

  @mcp_names ["FEEDBACK_O_TRON_MCP", "FEEDBACK_A_TRON_MCP", "MCP_SERVER"]
  @http_names ["FEEDBACK_O_TRON_HTTP", "FEEDBACK_A_TRON_HTTP"]
  @port_names ["FEEDBACK_O_TRON_HTTP_PORT", "FEEDBACK_A_TRON_HTTP_PORT"]
  @bind_names ["FEEDBACK_O_TRON_HTTP_BIND", "FEEDBACK_A_TRON_HTTP_BIND"]

  @tools [
    FeedbackATron.MCP.Tools.SubmitFeedback,
    FeedbackATron.MCP.Tools.ResearchFeedback,
    FeedbackATron.MCP.Tools.SynthesizeFeedback
  ]

  @type config :: %{
          mcp_stdio: boolean(),
          http: boolean(),
          http_port: 1..65535,
          http_ip: :inet.ip_address()
        }

  @spec config(keyword(), %{optional(String.t()) => String.t()}) :: config()
  def config(app_env, sys_env) when is_list(app_env) and is_map(sys_env) do
    %{
      mcp_stdio: pick(app_env, :mcp_stdio, on?(first_present(sys_env, @mcp_names))),
      http: pick(app_env, :http, on?(first_present(sys_env, @http_names))),
      http_port: pick(app_env, :http_port, parse_port(first_present(sys_env, @port_names))),
      http_ip: pick(app_env, :http_ip, parse_ip(first_present(sys_env, @bind_names)))
    }
  end

  @spec children(config()) :: [{module(), keyword()}]
  def children(%{} = config) do
    mcp_children(config) ++ http_children(config)
  end

  defp mcp_children(%{mcp_stdio: true}) do
    [
      {FeedbackATron.MCP.Server,
       name: "feedback-o-tron",
       version: Application.spec(:feedback_a_tron, :vsn) |> to_string(),
       tools: @tools}
    ]
  end

  defp mcp_children(_), do: []

  defp http_children(%{http: true, http_ip: ip, http_port: port}) do
    if port_free?(ip, port) do
      [{Bandit, plug: FeedbackATron.HTTPIntake.Router, scheme: :http, ip: ip, port: port}]
    else
      Logger.warning(
        "HTTP intake not started: #{:inet.ntoa(ip)}:#{port} is already in use; " <>
          "another feedback-o-tron serve may own it"
      )

      []
    end
  end

  defp http_children(_), do: []

  defp port_free?(ip, port) do
    case :gen_tcp.listen(port, ip: ip, reuseaddr: true) do
      {:ok, socket} ->
        :ok = :gen_tcp.close(socket)
        true

      {:error, _} ->
        false
    end
  end

  defp pick(app_env, key, fallback) do
    case Keyword.fetch(app_env, key) do
      {:ok, value} -> value
      :error -> fallback
    end
  end

  defp first_present(sys_env, names) do
    Enum.find_value(names, fn name -> Map.get(sys_env, name) end)
  end

  defp on?(nil), do: false

  defp on?(value) when is_binary(value) do
    String.downcase(String.trim(value)) in ["1", "true", "yes", "on"]
  end

  defp parse_port(nil), do: @default_port

  defp parse_port(value) do
    case Integer.parse(String.trim(value)) do
      {port, ""} when port in 1..65535 -> port
      _ -> @default_port
    end
  end

  defp parse_ip(nil), do: @default_ip

  defp parse_ip(value) do
    case :inet.parse_address(String.to_charlist(String.trim(value))) do
      {:ok, ip} -> ip
      {:error, _} -> @default_ip
    end
  end
end

# SPDX-License-Identifier: MPL-2.0
# Copyright (c) Jonathan D.A. Jewell <j.d.a.jewell@open.ac.uk>
defmodule FeedbackATron.EscriptSmokeTest do
  @moduledoc """
  End-to-end tests of the built binary. Tagged :escript and excluded by
  default; run with `mix escript.build && mix test --only escript`.
  """
  use ExUnit.Case, async: false

  @moduletag :escript
  @moduletag timeout: 60_000

  @bin Path.expand("../feedback-o-tron", __DIR__)

  @initialize ~s({"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}})

  setup_all do
    unless File.exists?(@bin) do
      flunk("#{@bin} is missing; run `mix escript.build` first")
    end

    :ok
  end

  test "--version prints the canonical version" do
    assert {"feedback-o-tron v1.0.0\n", 0} = System.cmd(@bin, ["--version"])
  end

  test "--help names serve and never the old spelling" do
    {out, 0} = System.cmd(@bin, ["--help"])
    assert out =~ "feedback-o-tron serve"
    refute out =~ "a-tron"
  end

  test "submit --dry-run sends nothing and exits 0" do
    args = ["submit", "--repo", "o/r", "--title", "T", "--body", "B", "--dry-run"]
    {out, 0} = System.cmd(@bin, args, stderr_to_stdout: true)
    assert out =~ "[DRY RUN] github: Would submit"
  end

  test "a real submit without a terminal is refused with exit 3" do
    args = ["submit", "--repo", "o/r", "--title", "T", "--body", "B"]
    {out, 3} = System.cmd(@bin, args, stderr_to_stdout: true)
    assert out =~ "Title:        T"
    assert out =~ "not a terminal"
  end

  test "serve answers initialize on stdout, nothing else, and exits 0 at EOF" do
    err = Path.join(System.tmp_dir!(), "fot-smoke-#{System.unique_integer([:positive])}.err")

    script =
      "printf '%s\\n' '" <> @initialize <> "' | '" <> @bin <> "' serve --no-http 2>'" <> err <> "'"

    {out, 0} = System.cmd("sh", ["-c", script])
    File.rm(err)

    [line] = String.split(out, "\n", trim: true)

    assert %{"id" => 1, "result" => %{"serverInfo" => %{"name" => "feedback-o-tron"}}} =
             Jason.decode!(line)
  end

  test "serve opens the HTTP intake and closes it when stdin closes" do
    {:ok, probe} = :gen_tcp.listen(0, ip: {127, 0, 0, 1})
    {:ok, port} = :inet.port(probe)
    :ok = :gen_tcp.close(probe)

    child =
      Port.open({:spawn_executable, @bin}, [
        :binary,
        :exit_status,
        args: ["serve", "--http-port", Integer.to_string(port)]
      ])

    health = "http://127.0.0.1:#{port}/health"

    assert wait_until(40, 250, fn ->
             match?(
               {:ok, %{status: 200, body: %{"status" => "ok", "service" => "feedback-o-tron"}}},
               Req.get(health, retry: false)
             )
           end),
           "HTTP intake never answered on #{health}"

    # Closing the port closes the child's stdin; the MCP loop sees EOF and
    # stops the VM, which is how an MCP host ends its server.
    Port.close(child)

    assert wait_until(40, 250, fn -> match?({:error, _}, Req.get(health, retry: false)) end),
           "HTTP intake still answering after stdin closed"
  end

  defp wait_until(0, _sleep_ms, _fun), do: false

  defp wait_until(tries, sleep_ms, fun) do
    if fun.() do
      true
    else
      Process.sleep(sleep_ms)
      wait_until(tries - 1, sleep_ms, fun)
    end
  end
end

== Task 11: The Justfile parses, and its recipes are this project's

*Files:*

* Rewrite: `Justfile`
* Modify: `tasks/Justfile:1`, `:5`
* Modify: `.machine_readable/contractiles/Justfile:1`, `:7`, `:87-94`

*Interfaces:*

* Consumes: the binary path `elixir-mcp/feedback-o-tron` (Task 9) and the
  `:escript` test tag (Task 10).
* Produces: `just build`, `just test`, `just lint`, `just fmt`, `just
  escript`, `just smoke`, `just serve`, `just install`, `just doctor`,
  `just clean`. Task 15's CI job calls `just lint` and `just smoke`.

=== Why it is broken

`just --list` fails with `unknown start of token '-'` at `Justfile:88:12`.
Line 88 is `if command -v panic-attack >/dev/null 2>&1; then`, written flush
against the left margin inside the `doctor` recipe body (lines 66-101). An
unindented line ends the recipe, so just parses `if command -v …` as a new
item; column 12 is the `-` of `-v`. Lines 110-113 and 152-161 have the same
shape in `heal` and `help-me`. Because the file does not parse, *no* recipe
runs — including the `must-*` and `trust-*` checks imported from
`contractile.just`. Those eight checks are unreachable, not failing: run by
hand in the worktree on 2026-09-08 all eight exit 0 (rehearsed).

The recipes themselves describe a different project. `build` runs `guix
build`, `check` runs `guix flake check` and `update` runs `guix flake update`
— `flake` is a Nix subcommand, not a Guix one; `fmt` calls `nixfmt` and
`lint` calls `statix`, both Nix tools. Nothing there compiles, tests or runs
the Elixir engine. `tour` describes `src/`, `ffi/`, `src/abi/` and `tests/`,
none of which exist in this repository.

Two further defects survive the parse fix, and both were measured:

. *`$$` is not a just escape.* `crg-grade`, `crg-badge` and the old `heal`
  use Makefile idiom: `grade=$$(grep …)`. just passes `$` through to the
  shell unchanged, so the shell receives a literal `$$(`, which is a syntax
  error under both `sh` and `bash`:
+
[source]
----
bash: -c: line 1: syntax error near unexpected token `('
error: recipe `crg-grade` failed on line 6 with exit code 2
----
+
These recipes have never worked. The fix is `$$` → `$` (rehearsed: with a
single `$` the recipe prints `C` from a `**Current Grade:** C` line and `X`
when `READINESS.md` is absent, which it is today).

. *Do not set `-e` on the shell.* The obvious hardening
  `set shell := ["bash", "-euo", "pipefail", "-c"]` silently breaks the
  grade fallback. `grade=$(grep -oP … READINESS.md | head -1)` exits 1 when
  the grep matches nothing; under `-e` the assignment's non-zero status
  aborts the recipe before the `[ -z "$grade" ] && grade="X"` fallback can
  run. Measured:
+
[source]
----
$ bash -euo pipefail -c 'grade=$(grep -oP "ZZZ" READINESS.md | head -1); echo "reached: [$grade]"'; echo "rc=$?"
rc=1                              # no output at all
$ bash -uo  pipefail -c 'grade=$(grep -oP "ZZZ" READINESS.md | head -1); echo "reached: [$grade]"'; echo "rc=$?"
reached: []
rc=0
----
+
Keep `set shell := ["bash", "-uc"]`, as today. just already fails a recipe
when any line exits non-zero, so `-e` buys nothing here and costs the
fallback.

== Build

== Run

[source,bash]
----
./feedback-o-tron serve
----

`serve` runs everything in one OS process and opens two doors:

[cols="1,3"]
|===
|Door |What it is

|MCP (stdin/stdout)
|JSON-RPC 2.0 for MCP hosts. The process exits when stdin closes, so a host
that goes away leaves no orphan.

|HTTP intake
|`127.0.0.1:7722`. `GET /health` answers
`{"status":"ok","service":"feedback-o-tron","intake":"http"}`.
|===

Close either with `--no-stdio` or `--no-http`; closing both is an error.
`--http-port N` moves the intake.

`FeedbackATron.Doors.config/2` is the single place that decides which doors
open. It reads application environment first, then OS environment:
`FEEDBACK_O_TRON_MCP`, `FEEDBACK_O_TRON_HTTP`, `FEEDBACK_O_TRON_HTTP_PORT`,
`FEEDBACK_O_TRON_HTTP_BIND`.

== The TCP transport

An optional third door, off by default, for hosts that speak line-delimited
JSON-RPC over a socket rather than over stdio:

[source,bash]
----
FEEDBACK_A_TRON_MCP_TCP=1 ./feedback-o-tron serve
----

It binds `127.0.0.1:7979`. `FEEDBACK_A_TRON_MCP_TCP_PORT` and
`FEEDBACK_A_TRON_MCP_TCP_BIND` change that.

NOTE: These three names keep the older `A_TRON` spelling because that is what
`mcp/server.ex` reads. Renaming the `FeedbackATron` namespace is a separate,
mechanical follow-up; until it lands, this document prints the names the code
actually looks for.

Smoke-test it with `scripts/mcp_tcp_smoke_test.sh`, which needs `nc`
installed and the server already running.

== Tools the MCP door offers

Three, registered in `application.ex`:

[cols="1,3"]
|===
|Tool |What it does

|`submit_feedback`
|Draft and (outside SP1b) submit a report to one or more platforms.

|`research_feedback`
|Look for existing reports before filing a new one.

|`synthesize_feedback`
|Turn a rough description into a structured report.
|===

`migration_observe` is implemented under `mcp/tools/` but is *not* registered,

== Nothing sends without a person

`submit` prints the entire payload and waits for a typed `y`. With no
terminal on stdin it refuses and exits 3. There is no `--yes` flag. Use
`--dry-run` to print the payload and send nothing.

The MCP and HTTP doors accept and draft reports; they do not send.

=== The Dialyzer job is a required-looking check that cannot fail

`.github/workflows/elixir-ci.yml:87-146` defines a job named `Dialyzer`
whose only real step is `run: mix dialyzer` with `continue-on-error: true`.
`dialyxir` is not in `elixir-mcp/mix.exs`'s `deps/0`; it appears in this tree
only inside `elixir-mcp/deps/*/mix.exs`, which are other packages' own
dev-dependency lists and are never fetched. So the step runs, exits 1 with
`** (Mix) The task "dialyzer" could not be found`, and `continue-on-error`
reports it as a success. The check has been green on every PR while running
no static analysis at all. Task 15 carries the full measurement.

One thing changes the cost of the repair, and it was measured after Task 15
was written. The workflow's own header comment (lines 9-12) says "Dialyzer is
a REQUIRED status check, so it must report on every PR", and that is what the
`continue-on-error` shim exists to satisfy. It is no longer true. The
`Optimus-Branch` ruleset on the default branch requires exactly three
contexts:

[source]
----
CodeQL
CodeRabbit
governance / Code quality + docs
----

`Dialyzer` is not among them. Dropping `continue-on-error: true` therefore
cannot block a merge — the check is not required, so a red one is advisory.
The shim is guarding a constraint that no longer exists.

Two repairs, in increasing order of honesty:

. *Delete the job.* One line in `mix.exs` less to maintain, and no check that
  claims to do something it does not. This is the right answer if nobody
  intends to act on Dialyzer output.
. *Make it real.* Add `{:dialyxir, "~> 1.4", only: [:dev, :test], runtime:
  false}` to `deps/0`, add a PLT cache step (the PLT build dominates the
  runtime; without caching the job takes minutes on every run), and drop
  `continue-on-error`. Expect a first run that is red: this codebase has
  never been type-checked, and Dialyzer's opening report on an unseen
  codebase is not usually empty. That red-to-green is its own PR.

Do not do the third thing, which is to leave the shim and add dialyxir: that
produces a job that runs real analysis and still cannot fail, which is worse
than either arm because it looks like it works.
